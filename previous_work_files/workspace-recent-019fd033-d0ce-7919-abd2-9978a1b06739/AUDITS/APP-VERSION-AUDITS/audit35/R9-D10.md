## D9 — section-flip inference (masked-replay leader accounting)

**Root cause (`app/modules/replay.js`):** the prediction vector `p` is constructed leader-first — TA-led → `[raw.ta, d, raw.tb]`, TB-led → `[raw.tb, d, raw.ta]` — so **`p[0]` is always the leader's probability**. The leader-win accounting read:
```js
var leaderW = z.side === 'TA' ? p[0] : p[2];   // BUG
```
For a TB-led (away-led) fixture this read `p[2]` = the **home** share → away-leader wins were never counted in `leagueWins[].wins/hitRate` (an away-led league scored hitRate ≈ 0 regardless of results — flipped inference).

**Fix:** `var leaderW = p[0];` unconditionally (also simplified the share/strength bins to `p[0]`, which was already the leader via `max(p[0],p[2])`).

**Regression pin (`harness/acceptance-r9.js`, D9):** synthetic store — one league, away side wins all 30 matches (→ every zone is TB-led). Replay must report `hitRate = 100` (leader wins counted). Pre-fix this reported ≈ 0.

```
PASS D9: replay evaluated fixtures (n>0)
PASS D9: league entry exists with actionable count
PASS D9: TB-led leader wins are counted (hitRate 100, not flipped to ~0)
```

**Impact scope:** masked-replay league accounting (`leagueWins`) — used for the honest replay report and league-gate artifacts. The evidence engine / zone computation (parity 7/7 vs legacy) is untouched; the R4 DC-vs-evidence gate harness was already home-first and correct.

## D10 — zero-commit log honesty

**Root cause (`app/modules/ingest.js`):** a commit that stored nothing (all rows duplicates / already present) still logged `Pack committed: 0 matches, …` and returned success — because `added` counted `report.teams` which increments for **merged** identities too.

**Fix:** `added = report.matches + report.identitiesCreated + report.seasons + venues + sources + notes + ctx + mutes + forms` (new rows only). When `added === 0` the commit logs `data/commit-skip`: *"Nothing new to store — N row(s) were duplicates or already present; no commit made."* and returns `committed: false`.

**Regression pin (`harness/acceptance-r9.js`, D10):** commit the same staged pack twice — the second must report `committed:false, matches:0`, log `commit-skip` with the honest message, and never log a false `Pack committed: 0 …`.

```
PASS D10: first commit adds the row (committed true)
PASS D10: duplicate commit adds nothing (committed false, 0 matches)
PASS D10: log has commit-skip with honest message
PASS D10: no false "Pack committed: 0" entry
```
