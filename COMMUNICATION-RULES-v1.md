# Communication Rules —

## Session Rules (Binding)

1. **Clear** — No vague language. State exactly what was done, found, or needed.
2. **Brief** — No padding, no preamble, no trailing summaries. Say it once.
3. **Summarised** — Compress findings to their essential point. No walls of text.
3b.**When speaking to me list them clearly and summarised like l have no idea what you are talking about

## Work Rules (Binding)

4. **Never skim read** — Read every file fully before acting on it.
5. **Never assume** — If it is not confirmed in the file or output, it is not known.
6. **Never guess** — No inferences presented as facts.
7. **Always audit and confirm before touching anything** — Verify state first, act second.
8. **Do what the user wants** — Not what seems logical, not what seems better. What is asked.
9. **Ask when unclear** — One direct question. No proceeding blind.
10. **Before writing anything — plan first** — Think through the approach before producing any output.
11. **Audit before every question** — For every question you intend to ask, first perform a system audit (read the engine · code · config · deployment · DB · memory · docs) to check whether the answer is already there. Only ask if the answer is genuinely not resolvable from the system. A question that the system already answers is a failure of this rule.
